# DSLink Cloud base (FASE 5/9): account, social, presence, invites, signaling

> From FASE 6 the Cloud also stores the user's own ROMs, BIOS/firmware and saves in a private R2 bucket and the PWA is hosted only by the Worker (no Netlify): see [CLOUD_STORAGE.md](CLOUD_STORAGE.md). Token permissions and deploy steps there are the current ones.

The emulation stays on the phones. Cloudflare holds: accounts, profiles, cloud library **metadata**, friends, presence, invites, rooms and WebRTC signaling (phase 6 adds the user's own optional files and saves, see CLOUD_STORAGE.md).
It never runs melonDS or ROMs, never carries video/audio or DS radio frames, and never receives `refs.json`. No Containers, no TURN.

```
PWA (phone) ──HTTPS/WSS──> Cloudflare Worker ──> D1 (users, sessions, friends, blocks, catalog, library, invites)
     │                          └──> Durable Objects: Presence (per user), SignalRoom (per 6-digit code)
     └────────── WebRTC DataChannel P2P (DS radio) ──────────> other phone
```

## API (all under the Worker origin)
| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/passkey/{register,login}/{options,verify}`, `POST /api/auth/{register,login,logout}`, `GET /api/auth/sessions`, `DELETE /api/auth/sessions/:id`, `POST /api/auth/sessions/revoke-others`, `GET /api/me` |
| Social | `GET /api/users/search?q=`, `GET /api/users/:username`, `/api/friends`, `/api/friends/requests`, `/api/blocks` |
| Library | `GET/PUT /api/cloud/library`, `POST /api/cloud/library/sync`, `DELETE /api/cloud/library/:id`, `/favorite`, `/played`, `GET /api/catalog` |
| Presence | `POST /api/ws-ticket` then `GET /api/ws?ticket=` (WebSocket, one-shot ticket, no cookie on the socket) |
| Invites | `GET/POST /api/play/invites`, `POST /api/play/invites/:id/respond`, `DELETE /api/play/invites/:id` |
| Signaling | `POST /signal/create`, `/signal/join`, `/signal/state`, SSE events, offer/answer/ICE, leave |

Relation states: NONE / OUTGOING / INCOMING / FRIEND / BLOCKED. Presence: OFFLINE / ONLINE / NEL MENU / IN GAME (title from the catalog `game_id`, never file names).
Rooms: CREATED / WAITING / READY / STARTING / IN_GAME / DISCONNECTED / CLOSED. SDP/ICE live only in the Durable Object memory, never in D1.
Migrations: `cloud/worker/migrations/0001_*.sql`, `0002_cloud_base.sql` (versioned, applied with `wrangler d1 migrations apply`).

## Default configuration of the PWA (no `?signal=`)
`play/cloud-config.json` is generated by `scripts/package_pwa.sh`:
* **Same origin (recommended)**: PWA served by the Worker itself (static assets). Do not set anything. Cookies are first-party, so Safari/iPhone works.
* **Static host (Netlify)**: `DSLINK_CLOUD_URL=https://<worker> DSLINK_API_MODE=proxy scripts/package_pwa.sh` writes a `_redirects` that proxies `/api/*` to the Worker (first-party cookies, Safari-safe); signaling and presence go straight to the Worker.
  `DSLINK_API_MODE=direct` calls the Worker cross-origin (SameSite=None cookie + CORS allow-list with credentials); Safari blocks third-party cookies, so prefer `proxy` for iPhone.
  The Netlify origin must be listed in `ORIGINS` (`DSLINK_EXTRA_ORIGINS`).
* `?cloud=` / `?signal=` remain developer overrides only. Single Player never needs the Cloud (works with it offline).

## Deploy (needs YOUR Cloudflare credentials — not done from the development sandbox)
1. Cloudflare dashboard → My Profile → API Tokens → Create Token (custom): **Account / Workers Scripts: Edit**, **Account / D1: Edit**, **Account / Workers R2 Storage: Edit**, **Account / Account Settings: Read**.
2. GitHub repo → Settings → Secrets and variables → Actions: secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`. Optional variable `DSLINK_EXTRA_ORIGINS` (e.g. `https://my-test.netlify.app`).
3. Make sure a workers.dev subdomain exists (Workers & Pages → Overview).
4. Actions → **deploy-cloudflare** → Run workflow. It runs the guard, tsc + vitest, builds WASM + PWA, creates D1 `dslink`, applies migrations, deploys, sets `INTERNAL_TOKEN`, smoke-tests, and runs the public browser test.
5. Result: `https://dslink-cloud.<subdomain>.workers.dev` = Cloud API, `/signal` = signaling, `/play/` = PWA.

Same by hand: `python3 scripts/cf_prepare.py` (needs the two env vars; writes `cloud/worker/wrangler.prod.jsonc`), then in `cloud/worker`:
`npx wrangler d1 migrations apply dslink --remote -c wrangler.prod.jsonc && npx wrangler deploy -c wrangler.prod.jsonc`.

Variables (in `wrangler.jsonc`): `ORIGINS` (exact allowed origins, comma separated), `RP_ID`/`RP_NAME` (WebAuthn; RP ID is derived from the allowed Origin), `ENVIRONMENT`. Secret: `INTERNAL_TOKEN`.

## Local verification
